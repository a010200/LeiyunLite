# 雷云lite v1.0 宏使用说明

> 本文记录最初 WinForms 版的手动宏功能；其中窗口、暂停和“无录制”的描述只适用于该旧版。当前 WPF UI R3 已加入显式录制，操作步骤及限制请看根 [README](../README.md) 和 [UI-R3.md](UI-R3.md)。

## 原理

截图展示的是动作分类，不包含原软件内部实现。本版采用「保存动作序列 → 全局输入监听 → 匹配绑定 → 顺序执行」，并非复制截图软件的内部代码。

键盘/鼠标动作通过 Windows `SendInput` 执行，文字通过 Unicode 输入，不占用剪贴板。触发器通过专用消息线程的低级键盘/鼠标钩子监听；不记录普通键盘输入到日志或磁盘。模拟输入被排除，不会再次触发绑定。

## 动作

| 分类 | 用法 |
| --- | --- |
| 延迟 | 等待 0～600000 毫秒；不是硬实时定时 |
| 键盘功能 | 普通键或修饰键的点按、按下、松开 |
| 鼠标功能 | 左/右/中键、X1/X2 的点击、按下、松开；上下滚动 1～1000 格，不包含鼠标移动 |
| 调用宏 | 执行另一个宏后继续当前宏；禁止递归调用 |
| 启动 | 程序、文件或网址；使用系统关联应用打开，可填写参数 |
| 运行命令 | 分开填写可执行程序与参数，如 `cmd.exe` 和 `/d /c echo hello`；不自动包装为 shell 命令，也不等待退出 |
| 文本功能 | Unicode 文本；换行转为 Enter，制表符转为 Tab，效果由目标应用决定 |
| 循环 | 「循环开始」和「循环结束」包围动作，循环 1～1000 次，最多嵌套 8 层 |

命令与启动动作按当前用户权限执行，只填写你理解且信任的内容。停止宏不会终止已经启动的外部程序，也不能撤销已经输入的文字或执行过的命令。

## 示例

侧键输入文字：新建「常用回复」→添加文本动作→新增 X1 绑定→执行一次→保存→关闭编辑器→把光标放入目标输入框→按 X1。若不希望同时触发浏览器后退，勾选拦截原始动作。

模拟 Ctrl+C：依次添加「Ctrl 按下」「C 点按」「Ctrl 松开」。需要等程序响应时，加延迟动作。

触发组合里的物理 Ctrl/Alt/Shift/Win 在松开前可能影响目标程序。可在宏开头加适当延迟并松开触发键；本程序不强制松开你实际按住的键。优先选用侧键或不带修饰键的功能键。

循环：添加「循环开始（3 次）」→「A 点按」→「延迟 200 毫秒」→「循环结束」，绑定滚轮向上，执行一次。

## 运行规则

- 滚轮支持一次执行和开关执行，按累计 120 单位作为一格。开启拦截时也拦截不足一格的事件。快速滚动可能跨多格，因此开关模式更适合按键触发。
- 「保存并应用」保存全部配置并停止当前宏，以新快照替换运行配置。
- 「试运行」使用未保存草稿；隐藏编辑器后等待 3 秒执行，请切换目标窗口。
- 编辑器打开时绑定暂停；最小化编辑器也仍暂停，需要关闭或使用试运行隐藏它。
- Ctrl+Shift+F12、编辑器/托盘停止按钮均可取消宏，包括等待延迟期间。
- 按住重复在触发主键松开时停止；开关执行在再次按下时停止。忙碌时其他宏不会排队。
- 鼠标绑定只要求设置过的修饰键；未设置修饰键的中键等绑定不会因同时按住 Shift/Ctrl/Alt/Win 而失效。多个鼠标绑定同时符合时，优先选择要求修饰键最多的一项；同等具体程度按配置顺序选择。键盘绑定仍按精确组合匹配。松开无关实体键不会停止按住宏，主动停止按钮/快捷键仍然有效。
- 取消后，仍在 Windows 输入流中、尚未传给目标的本程序模拟按下事件会被低级钩子拦截，抬起事件继续放行；这不能撤回目标程序已经处理或排队的事件。
- 取消重复宏时会对本轮用过的鼠标键再补一次抬起，即使内部状态已显示抬起；每次模拟按下前也复查取消状态。宏页“复制输入时序”仅在内存保留右键/中键、宏状态及模拟左键按下/抬起计数，不记录其他按键内容或写入文件。Fluent UI候选默认隐藏诊断，需要正常退出当前实例后以`LeiyunLite.Desktop.exe --diagnostics`显式开启；诊断底层API不变。
- 最多 100 个宏、每个 500 个动作、200 个绑定，调用深度最多 16 层。单轮有 100000 操作预算，空循环也计入；包含显式延迟的重复宏不再附加隐藏轮次间隔，完全无延迟的重复宏保留 1 毫秒防忙循环保护。短暂执行停顿后不会压缩后续显式延迟来追赶旧时间轴。
- 拒绝重复启用同一触发组合、缺失目标、递归调用、未配对循环和占用紧急停止快捷键。

## 边界

不包含自动录制、鼠标移动轨迹、条件分支、按应用配置、特定物理鼠标选择或板载宏。延迟使用高分辨率计时器和单调时间轴，但 Windows 调度不是硬实时，1 毫秒是目标值而不是绝对保证。未保证每个游戏和高权限目标都接受用户态 `SendInput`；不要用于安全关键操作。强制结束进程、注销、系统故障时无法保证释放所有输入。

官方参考：[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[低级键盘钩子](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)、[低级鼠标钩子](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)。
